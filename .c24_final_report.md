## I. GLOBAL REQUEST IDEMPOTENCY

### GitHub-side marker reconciliation

```
<!-- autodev-review-request:v1:<provider>:<full_head_sha>:<request_id> -->
```

`_pr_already_has_pending_request` queries
`gh api repos/.../issues/.../comments --paginate` for an
existing AutoDev marker matching ``provider`` + ``full_head_sha``.
On match, NO post is dispatched. The marker MUST carry the
FULL 40-or-64-char hex head SHA; the legacy 12-char prefix
is rejected.

When a match is found, ``_adopt_existing_marker`` reconstructs
the local ledger with the discovered ``request_id`` so the
per-head cap / cooldown machinery sees a coherent local
record across supervisor lifetimes. Most-recent marker
(by ``created_at``) is chosen when multiple historical
duplicates exist.

### Cross-state-dir test

``test_7_concurrent_supervisors_emit_at_most_one_mutation``
verifies the audit's case 7: a second supervisor with a
different state directory, scanning the live PR, sees the
existing AutoDev marker and DOES NOT post a duplicate. The
canonical post path is:

```
schedule_codex_request_on_stable_head()
  -> post_review_request(provider, head_sha)
       -> _pr_already_has_pending_request(provider, head_sha)
            -> if True: _adopt_existing_marker(...) + return True
       -> if adopted: return without posting
       -> gh pr comment (only when no marker exists)
```

### Mutation-success/local-write-crash test

``test_10_remote_success_local_write_crash_is_reconciled``
covers the audit's case 10: when ``gh pr comment`` succeeded
but the local ``REQUEST_SENT`` write crashed, the supervisor
restart sees the GitHub marker and adopts the discovered
``request_id`` into the local ledger. No repost.
