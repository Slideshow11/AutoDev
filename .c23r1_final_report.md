## C. CORRECTED REVIEW-SELECTION ALGORITHM

`autocoder_supervisor/reviewer_policy.py::_provider_review_record_for_head`
walks ALL formal reviews for the provider and selects by priority:

1. **ANY formal review with `commit_id == head_sha`** wins
   (exact-head anchor). Among multiple exact-head matches,
   the most-recent by `submitted_at` wins.
2. **`provider_surfaces[provider].heads[head_sha]`** also
   wins (per-head binding persisted at snapshot time).
3. Otherwise the **most-recent STALE** formal review (commit_id
   differs), selected by `submitted_at` descending.
4. Otherwise the **most-recent UNBOUND** formal review
   (no commit_id).
5. Fallback to the most-recent issue comment by
   `created_at` (no commit_id available).

An exact-head formal review ALWAYS wins regardless of
position in the snapshot. The helpers
`_most_recent_review` / `_most_recent_comment` provide the
sorting primitive (ISO-8601 → Unix-seconds → max with stable
fallback).

## D. INITIAL-VS-REPAIR REVIEWER POLICY

Phase vocabulary (round-C23R1):

- `PHASE_INITIAL_HEAD`: no `control_plane.repair_pushed`
  event has been observed for the current PR run.
- `PHASE_REPAIR_HEAD`: at least one worker push has been
  observed.

Phase signal source: the controller's state-machine journal
persists every transition with `event=control_plane.repair_pushed`
(round-54/C22 §4). `resolve_phase_from_state_root` reads the
per-run `state.json` and counts those entries. Production
heartbeat: `apply_reviewer_plan` calls
`resolve_orchestration_state_root(...)` to find the state
root, then `resolve_phase(state_root=...)`. Tests can pass
`explicit_phase=` or seed a synthetic journal.

Default policy (per `DEFAULT_POLICY_PROFILES`):

| Provider | INITIAL_HEAD                | REPAIR_HEAD                  |
|----------|-----------------------------|------------------------------|
| Codex    | required + auto-trigger + 1/head, unlimited/PR | required + auto-trigger + 1/head, unlimited/PR |
| Sourcery | optional + no-auto-trigger + 0/head, never triggers | optional + no-auto-trigger + 0/head, never triggers |
| CodeRabbit | **required** + auto-trigger + 1/head + 1/PR (initial review) | **OPTIONAL** — `max_per_head=0`, `budget=0` (phase-disabled) |

`ReviewerPolicy` gains per-phase overrides
(`phase_required`, `phase_budget_per_pr`,
`phase_max_requests_per_head`, `phase_auto_trigger`) plus a
`value_for_phase(attr, phase)` helper. When the override is
empty the legacy scalar wins; otherwise the phase's value
wins.

## E. CORRECTED CODERABBIT QUOTA BEHAVIOR

The audit's required behaviour:

- Initial CodeRabbit review: **REQUIRED**; one explicit request
  may be consumed; consumed on the initial head only.
- Subsequent repair heads: **OPTIONAL** by default. Stale
  CodeRabbit evidence on a repair head is
  `OPTIONAL_STALE` / `NOT_NEEDED`. The readiness gate does
  NOT block.
- The operator's limited CodeRabbit quota is consumed by
  the initial review only.

Implementation:

```python
# DEFAULT_POLICY_PROFILES["coderabbit"]
"phase_required": {
    PHASE_INITIAL_HEAD: True,
    PHASE_REPAIR_HEAD: False,    # C23R1 fix
},
"phase_budget_per_pr": {
    PHASE_INITIAL_HEAD: 1,
    PHASE_REPAIR_HEAD: 0,        # phase-disabled
},
"phase_max_requests_per_head": {
    PHASE_INITIAL_HEAD: 1,
    PHASE_REPAIR_HEAD: 0,        # phase-disabled
},
"phase_auto_trigger": {
    PHASE_INITIAL_HEAD: True,
    PHASE_REPAIR_HEAD: False,    # never auto-trigger on REPAIR
},
```

The planner's budget/budget-per-head gates now respect
`phase_max_requests_per_head == 0` and `phase_budget_per_pr == 0`
as phase-disabled and emit `NOT_NEEDED` for optional
providers (or `BLOCK` for required providers with
`budget=0`, signalling contradictory policy).

## F. REQUEST ACCOUNTING REPAIR

`_count_active_request_records` previously computed a
binary `max(0, 1 - superseded_for_provider)` that conflated
per-head cap accounting with PR-lifetime budget accounting
and subtracted unrelated superseded records from the
current-head count.

New algorithm returns a tuple
`(active_on_current_head, active_in_pr_lifecycle)`:

1. Group superseded records by `(provider, head_sha)` for the
   per-head subtraction. Records whose `superseded_head` does
   not match the current head are NOT subtracted from the
   current-head count.
2. Walk the canonical `{provider}__{head}.json` files
   (skipping `*.superseded.json` variants). Each file with a
   non-SUPERSEDED lifecycle contributes to
   `in_pr_lifecycle`.
3. For the current head only: subtract the count of
   superseded records whose `superseded_head == head_sha`
   from the current-head's active records.

Tests cover the audit's required scenarios:

- zero requests
- one current-head request
- previous-head active record (does not count for current)
- superseded subtraction (current-head count unaffected)
- multiple previous heads
- current-head + superseded histories
- CodeRabbit PR budget of 1 (the audit's quota-1 case)
- Codex unlimited PR budget with one/head cap
