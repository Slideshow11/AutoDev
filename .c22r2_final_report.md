## D. AUTHORITATIVE SUPERSEDING EVIDENCE

**`FindingLedger.superseded_repair_transition(finding_id)`** — the durable JSONL-backed ledger entry recorded by `loop.mark_head_advanced(old_head_sha, new_head_sha, directive_id=...)` at the moment the supervisor's `mark_head_advanced_public` observes a verified worker push.

**Schema extension (audit's "small schema extension is acceptable ONLY if required"):**

- `FindingLedger.mark_superseded_by_head` gains optional `new_head_sha=` and `directive_id=` keyword arguments. When passed, the SUPERSEDED row carries `superseded_by_head` (the authoritative new head SHA) and `directive_id` (the relay directive UUID that drove the head advance). Without these, the legacy row shape is preserved (backward compat).
- `WorkerAttemptRecord` gains an optional `directive_id: Optional[str] = None` field (placed at the end of the dataclass to preserve field-order contract) so the supervisor's `mark_head_advanced_public` can forward the directive UUID that drove the worker push to the loop.

**Why this evidence identifies the actual repair rather than an unrelated descendant:**

1. The controller's `report_repair_pushed(head_observed=new_head_sha)` is the AUTHORITATIVE state transition that fires only on a positively-verified worker push (round-36 invariant: `HEAD_ADVANCED != REPAIR_PUSHED`; verified worker-attempt provenance required).
2. The SUPERSEDED row is appended to the durable `finding_ledger.jsonl` AT THE MOMENT of this transition. It cannot be polluted by an unrelated docs commit because the docs commit does not fire `report_repair_pushed` (only the worker push does).
3. The audit's `superseded_at` (wall-clock at the moment of the transition) is durable in the JSONL log; the relay's eligibility helper compares the follow-up's `createdAt` against this authoritative timestamp.
4. A later documentation/report-only commit does NOT shift the boundary because the JSONL row's `superseded_at` is the original repair-push time, not the current head's commit time.

**Backward compat:** C22-R1's `superseding_repair_committed_at` (git-ancestry field) is still stamped on the snapshot for diagnostic provenance but the C22-R2 helper does NOT consult it. The audit's contract: "Do NOT fall back to ... git-ancestry." When `superseded_at` is missing or malformed, the rule fails closed.
