## D. FRESHNESS CONTRACT

A review result is fresh only when it is bound to the current
exact head. The strongest available evidence is consulted in
order:

1. **`formal_reviews[*].commit_id == head_sha`**: GitHub's
   review submission anchor. STALE when the commit_id differs
   from the current head.
2. **`provider_surfaces[provider].heads[head_sha]`**: explicit
   per-head binding persisted by `capture_live_snapshot`.
3. **Issue comments** by the provider's bot_logins: bound by
   wall-clock only; freshness is conservative (not used to
   short-circuit a known-stale formal review).
4. **Request ledger**: REQUEST_INTENT / REQUEST_SENT /
   ACKNOWLEDGED records mark an in-flight request; the
   provider's terminal evidence is not yet on the current head.

A STALE result on a required provider triggers REQUEST (or
BLOCK on budget exhaustion). The C22-R1 codex review on PR #8
is anchored to commit `fbe10d7...` (the pre-C22-R1 head) and
is therefore STALE on the current head `1634d09...` — exactly
the case the directive requires AutoDev to detect and remediate.

## E. DURABLE REQUEST STATE

The supervisor's existing review-request ledger (round-54/C22 §4)
is the canonical persistence path. C23 reads it and never
duplicates writes:

```
REVIEW_REQUESTS_DIR/
  {provider}__{head_sha}.json            ← active request (lifecycle: REQUEST_INTENT/REQUEST_SENT/...)
  {provider}__{head_sha}.superseded.json ← prior head's request, moved on head advance
```

`apply_reviewer_plan` reads both files when computing the per-head
dedup cap and the lifetime PR budget. The schema extension is
zero — C23 reuses the existing format.

Restart behaviour: if the supervisor process dies between
REQUEST_INTENT and REQUEST_SENT, the next slice observes the
existing `REQUEST_INTENT` record and routes to `WAITING_FOR_AUTO`
(within the cooldown window) or `NOT_NEEDED` (after a fresh
review has been observed). No restart ever re-issues a request
for a head that already has one in flight.

## F. CODEX TRIGGER

- **Mechanism**: the supervisor's canonical
  `post_review_request(provider, head_sha)` seam (round-54/C22
  §4). The seam verifies the live PR head matches the
  requested head before sending; if not, the prior head's
  request is marked SUPERSEDED.
- **Dedup**: `max_requests_per_head=1` per head. A second
  request on the same head returns
  `max_requests_per_head_reached` (BLOCK).
- **Cooldown**: `request_cooldown_seconds=600` (10 min)
  prevents immediate retries even when budget allows.
- **Grace period**: `freshness_grace_seconds=180` (3 min) for
  providers that auto-run on pushes. AutoDev waits the grace
  period before issuing its own trigger so a same-tick
  auto-review is not double-fired.

## G. CODE RABBIT BUDGET

- `budget_per_pr=1` (initial-only)
- `max_requests_per_head=1`
- A second explicit request on the same head returns
  `BLOCK` with reason `max_requests_per_head_reached` or
  `budget_per_pr_exhausted`
- AutoDev does NOT consume CodeRabbit quota to make tests
  pass — the test fixtures verify BLOCK semantics without
  sending live requests

## H. QUALIFICATION CHANGES

`evaluate_readiness` now consults `snap["reviewer_plan"]` after
the existing checks (CI / pagination / provider-surface / threads
/ events). ANY plan value other than `NOT_NEEDED` blocks
qualification with reason `required_reviewer_pending`:

- `REQUEST`: review request in flight; required reviewer
  evidence is not yet on the current head
- `WAITING_FOR_AUTO`: grace period not yet expired OR a prior
  request is within its cooldown
- `BLOCK`: budget exhausted, policy disallows trigger, or
  `max_requests_per_head` reached

Legacy snapshots without `snap["reviewer_plan"]` keep their
prior behaviour (the planner is opt-in via the heartbeat
helper).

## L. AUTONOMY IMPACT

**Can AutoDev now handle:**
```
new repair head
→ missing fresh Codex review
→ automatic request
→ wait
→ ingest
without operator action?
```

**YES.**

The C23 layer's exact behaviour on the next repair push:

1. `loop.mark_head_advanced(old, new)` advances the durable
   ledger; the controller's state machine transitions to
   AWAITING_CI.
2. The supervisor's heartbeat loop calls
   `capture_live_snapshot(...)` for the new head.
3. The heartbeat loop calls `apply_reviewer_plan(snap,
   head_sha=new, post_review_request_fn=post_review_request)`.
4. The planner computes: codex = `REQUEST` (no fresh
   exact-head review); coderabbit = `REQUEST` (no fresh
   exact-head review); sourcery = `NOT_NEEDED`.
5. The heartbeat loop calls `post_review_request("codex",
   new)` and `post_review_request("coderabbit", new)`. The
   canonical seam persists REQUEST_INTENT, posts the
   `@codex review` and `@coderabbitai review` comments via
   `gh pr comment`, then advances to REQUEST_SENT.
6. `evaluate_readiness(snap, head=new)` returns
   `{ready: False, reason: 'required_reviewer_pending',
   required_reviewer_blockers: [{provider: codex, action:
   REQUEST}, {provider: coderabbit, action: REQUEST}]}`.
7. The supervisor's quiet-window polls continue. On the
   next slice where the ledger has advanced to ACKNOWLEDGED
   and `provider_surfaces` carries the new head binding, the
   planner emits `NOT_NEEDED` for both providers.
8. `evaluate_readiness` returns `{ready: True, reason:
   'quiet_window_match'}`.

The operator no longer types `@codex review` after a repair
head. The autonomy gap is closed.
