## H. AUTONOMY DEFECTS

### AUTONOMY_DEFECT_1: `ORCHESTRATOR_STATE_ROOT_BOOTSTRAP_MISSING` (observed live)

**Severity**: blocks LEVEL B / LEVEL C achievement.

**Reproduction**:
```
[error] orchestration_root unresolved; recoverable retry; event stays actionable; supervisor schedules retry
[warning] _advance_awaiting_ci_to_qualifying: orchestration root unresolved
[warning] qualifying-head reopen: orchestration state root unresolved
```

**Root cause**:
- The supervisor's main loop expects an orchestrator state root (the per-run state root where the controller's state machine, journal, and FindingLedger live) to be positively identified at boot.
- The supervisor itself does NOT bootstrap this root from scratch; it requires either:
  - `AED_ORCHESTRATION_STATE_ROOT` env var pointing at a pre-existing root with `state.json` and `run_context.json`, OR
  - `RUN_STATE['orchestration_state_root']` field set by an earlier supervisor lifetime.
- Without this root, the controller is stuck in `AWAITING_CI`, the relay's `_advance_awaiting_ci_to_qualifying` helper fails closed, and the relay's `RelayLoop.run_once` refuses every invocation ("relay returned recoverable_retry; events remain actionable; supervisor continues polling without generic worker").
- The trial cannot bootstrap the root from the outside without manual intervention, which is forbidden by the directive.

**Preserved evidence**: `[REDACTED-HOME]/AutoDev/.autonomy_trials/1c/` (state files, poll summary, final iteration log).

## M. DIRECT ANSWER

> Can the operator now start AutoDev once, leave for several hours, and return to a PR waiting only for human merge approval?

**NO**

Reason: The canonical AutoDev supervisor cannot bootstrap its own orchestrator state root from scratch. Once the controller is in `AWAITING_CI` and no orchestrator state root exists on disk (which is the case for any cold-start PR), the relay refuses every invocation. Codex findings (or any other actionable review evidence) accumulate in the unconsumed-events ledger but never drive a worker launch. The trial reached LEVEL A only because the C23 path automatically posted `@codex review` (a pre-supervisor-C23 path that doesn't require the orchestrator state root). Beyond that, AutoDev blocks on the bootstrap gap until something external initializes the orchestrator state root.

**Partial credit (LEVEL A achieved)**: AutoDev itself triggers fresh-review requests (the directive's primary gap-closing requirement). This is a real autonomy improvement over the pre-C23 manual-`@codex`-review world.

**Required for LEVEL B/C**: an upstream orchestrator bootstrap step (e.g. `autocoder_orchestration.cli init` or an external `make_pr` lifecycle) must initialize the orchestrator state root + controller state machine before the supervisor can launch workers. This is outside the C23/C23-R1 reviewer-orchestration scope and is the next engineering cycle's responsibility.
