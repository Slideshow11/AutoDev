## D. REPAIR

### Semantic eligibility rule

`_maybe_resurrect_outdated_thread(thread_data, *, current_head, operator_logins)` returns either `None` or `{"followup": <reply-dict>, "thread_id": <id>}`. The eligibility rule is the conjunction of three sub-rules:

- **R1 (non-operator author)**: `followup.author` must NOT be in `operator_logins`. Default `operator_logins` is `_C22_DEFAULT_OPERATOR_LOGINS = ("github-actions", "github-actions[bot]")`; the snapshot may override via `snapshot["operator_logins"]`. Operator explanations can address a finding without re-elevating it.
- **R2 (strictly-later timestamp)**: `followup.createdAt > thread.top_createdAt`. Missing or unparseable timestamp → fail closed (return None).
- **R3 (actionable body)**: `followup.body` must pass the existing `_is_actionable_provider_comment` filter so status markers like "Walkthrough" do not resurrect threads.

The rule trusts the caller to enforce `outdated=True` AND `resolved=False` as pre-conditions; the helper double-checks both defensively.

### Evidence-binding rule

GitHub payload fields used (in `capture_live_snapshot`'s `reviewThreads` GraphQL query):

| Field | Captured since C22 | Used by |
|-------|---------------------|---------|
| `comment.databaseId` | existing | reply `id` |
| `comment.body` | existing | thread `body` (first), reply `body` |
| `comment.path` | existing | thread `path` |
| `comment.line` | existing | thread `line` |
| `comment.commit.oid` | existing | thread `commit_oid` (current-head binding; unused for outdated threads because GitHub doesn't re-bind) |
| `comment.author.login` | existing for first, **C22 for replies** | R1 check |
| `comment.createdAt` | **C22 for first + replies** | R2 check |
| `comment.updatedAt` | **C22** | thread-proof fingerprint sensitivity |

The strongest durable binding evidence is **`createdAt` ordering inside the same thread**. This is documented inline at
`review_repair_relay.py:_c22_is_followup_eligible`. There is no commit binding available for outdated-thread replies because GitHub does not re-bind them.

### Finding shape (no schema change)

The resurrected Finding reuses `Finding` fields 100%:

- `finding_id = "thread:<thread_id>"`
- `source = "review_thread"`
- `severity = _classify_severity(followup.body)`
- `title = followup.body.splitlines()[0]`
- `body = provenance_prologue + followup.body` where `provenance_prologue` carries `thread_id`, `triggering_comment_id`, `triggering_author`, `triggering_createdAt`, `outdated: true`, `current_head`, `original_thread_comment_id`, `thread_path`, `thread_line` as a structured header
- `file_path = thread.path` (the original anchor)
- `line = thread.line`
- `comment_id = int(followup.id)` (the follow-up's databaseId)
- `suggested_test = _extract_suggested_test(followup.body)`
