## B. REPO.PUSHED_AT DEFECT (audit §1, §2, §3)

**Reproduction** (`tests/test_c24r2_false_push_time.py`):

- Helper `_fetch_pr_head_pushed_at` reads `head.repo.pushed_at` from GitHub's PR payload.
- `head.repo` is a REPOSITORY object, not a ref/shadow-object. `repo.pushed_at` is the repository's most-recent push, mutated by pushes to ANY branch in the same repo.
- Test reproduction: A PR repair head B is pushed at T1. Another branch is pushed at T3. The pre-fix helper returns T3 (the repo time) as B's push time. A genuinely-post-push follow-up at T2 (T1 < T2 < T3) is rejected.

**Live execution confirmed the defect**:

```
helper returned: '2026-08-20T14:00:00Z'   ← repo-level push time
                          (the audit's documented false binding)
```

**Why it was invalid**: `head.repo.pushed_at` is the REPOSITORY's most-recent push. A push to any other branch in the same repository moves `repo.pushed_at` while the PR head SHA is unchanged. Per audit §1, the binding is invalid.

**Fix**: `_fetch_pr_head_pushed_at` is now a no-op stub returning `""`. The helper is preserved for legacy import compatibility but is not authoritative. The C24-R2 contract replaces push-time proxy with an exact-head follow-up binding (`commit_id` on the follow-up), per audit §3/§5.

**Regression test status**: `tests/test_c24r2_false_push_time.py` had 2 tests failing against the pre-fix implementation (helper returned T3; helper source contained `repo.pushed_at`). After the C24-R2 fix, all 5 tests in that file pass.

## C. FINAL REPAIR BINDING (audit §3, §5)

**Preferred solution** (exact-head follow-up binding):

The canonical resurrection contract is the per-follow-up `commit_id` (and `original_commit_id`) field on the review comment. GitHub's REST API returns these fields for both review-thread comments (`/pulls/{n}/comments`) and formal reviews (`/pulls/{n}/reviews`).

Live evidence (PR #9 review comments): each comment carries a `commit_id` and `original_commit_id`. Example:
```
id=3817486185  commit_id=fc3661fbc79618c8d734561cbbf2dae87938bf7b
               original_commit_id=9b9205d1ad168503c9baa6e3bea4ed6a0361177d
```

A follow-up qualifies for resurrection when:
- `followup.commit_id == superseded_by_head` (the new repair head)
- OR `followup.original_commit_id == superseded_by_head`

This is the audit's preferred exact-head identity contract. When the binding is established, the timestamp comparison in `_c22_is_followup_eligible` is RELAXED. When the binding is to a DIFFERENT head, the follow-up is REJECTED unconditionally. When the binding is absent, the legacy timestamp comparison is in force.

**Code change** (`autocoder_orchestration/review_repair_relay.py`):

```python
def _c22_is_followup_eligible(
    *,
    followup: dict,
    repair_transition_ts: Optional[int],
    operator_logins: Tuple[str, ...],
    superseding_head: Optional[str] = None,
) -> bool:
    ...
    if superseding_head:
        cmt = (followup.get("commit_id") or followup.get("original_commit_id"))
        if isinstance(cmt, str) and cmt:
            if cmt == superseding_head:
                return True   # exact-head binding match: post-repair
            else:
                return False  # bound to a different head: not post-repair
    if followup_ts <= repair_transition_ts:
        return False
    ...
```
